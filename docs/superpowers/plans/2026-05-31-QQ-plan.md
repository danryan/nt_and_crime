## Outcome

Shipped. Host 7/7 (102 assertions). ARM `.text` 35518 B. Full OC-app suite (13
binaries) and ARM regression (Cumulus, Harrington1200, POLYLFO, DQ, ASR) clean.

The HSIOFrame.h risk flagged in the brainstorm materialized as a hard blocker, not
a mechanical poison: `APP_QQ.h` (and `APP_SEQ.h`) `#include "HSIOFrame.h"` (used by
neither), and the vendor `HSIOFrame.h`/`HSUtils.h` are `#pragma once` resolved
same-dir to the vendor copies, which collide with the shim's own `HSUtils.h`
shadow that every OC TU pulls via `globals.cpp` (redefinition of `HEM_SIDE`,
`QuantEngine`, `PackLocation`, `calibr8`). Shadowing structurally cannot win. The
fix, decided with the user, is the first `vendor-patches/` provisioning patch
(`0001-oc-apps-drop-vestigial-hsioframe.patch`), applied idempotently by
`bootstrap.sh`, stripping the dead include from both headers. This established the
documented one-and-only exception to the never-edit-vendor rule (CLAUDE.md
"Vendor provisioning patches"); it also unblocks SEQ (#52), which shares the
include. Two more deltas the brainstorm did not foresee: `multiply_u32xu32_rshift32`
must be defined locally in QQ.cpp (vendor `dspinst.h` defines it for ASR/DQ, so the
shared shim `util_math.h` cannot), and the output-smoke test must drive the four
trigger buses (QQ channels are trigger-clocked and all-MAIN-pitch, so an untriggered
run reads all-zero).
