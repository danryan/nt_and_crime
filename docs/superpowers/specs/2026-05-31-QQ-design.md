# Design: QQ (Quantermain) NT plug-in

Date: 2026-05-31
Status: implemented
Vendor SHA: 7800d929f25868f9a8b7d3d50514532ee001649b
Issue: #50

Implements the audit in `../brainstorms/2026-05-31-QQ-brainstorm.md`. The DQ
quad-facade template at N = 4 with a single per-channel mask skip.

## Recipe

`plugins/apps/QQ.cpp` follows the DQ multi-channel template:

1. `#define NT_OC_APP_TU 1`; `#include "UI/ui_events.h"` FIRST (OC::UI alias for
   the vendor `OC::ScaleEditor<QuantizerChannel>` member of `qq_state`).
2. Include the runtime, dispatch, the OC shim headers, `Arduino.h`,
   `util/util_settings.h`, `util/util_turing.h`, `util/util_math.h`, and
   `util/util_logistic_map.h` (vendor header-only, pure int math).
3. `namespace menu = OC::menu;`. `uint_fast8_t MENU_REDRAW = 1;`.
4. `#define ENABLE_APP_QUANTERMAIN 1`; `#include "APP_QQ.h"`.
5. Subset: exclude the U16 `CHANNEL_SETTING_MASK` (index 2). `phys_in_channel(w) =
   w < 2 ? w : w + 1`, `kExposedPerChannel = CHANNEL_SETTING_LAST - 1 = 50`,
   `kNumChannels = 4`, `kNumSettings = 200`. Build the dual/quad facade
   (instance = `quantizer_channels` base; get/apply/value_attr index
   `[idx / kExposedPerChannel]` and remap `idx % kExposedPerChannel`); override
   save/restore/storage_size to `QQ_save`/`QQ_restore`/`QQ_storageSize` (the four
   channels are a separate array, not one SettingsBase, so the whole-app blob is
   load-bearing). `param_name` returns channel-prefixed names from
   `char g_names[200][16]`.
6. `.customUi = dispatch_custom_ui_factory<true>` (QQ reads
   `EVENT_BUTTON_LONG_PRESS`).
7. Test seams: `qq_get_setting`/`qq_apply_setting` (channel, physical),
   `qq_num_channels`, `qq_exposed_per_channel`, `qq_setting_count` (200),
   `qq_settings_param_base`, `qq_phys_in_channel`, `qq_get_mask`/`qq_set_mask`,
   `qq_get_outputs`, `qq_arm_sentinel`.

### Manifest

`shim/include/oc_app_manifests/QQ.h`: GUID `OCQQ`, name "Quantermain". 4 CV in, 4
CV out (the four channels' pitch), 4 trig in (per-channel clocks).

### Shared-surface change

`kMaxSettings` 160 -> 208 in `plugins/apps/_per_app_runtime.h` (200 flat rows).
DATA-only (per-instance arrays in `req.sram`); `.text` unchanged. On-device:
deploy then power-cycle once to re-cache `calculateRequirements` for all OC apps.

### Makefile

`OC_APP_LIST += QQ`; `VENDOR_DEPS_QQ := build/arm/vendor_src/peaks_bytebeat.o`,
`VENDOR_DEP_HOST_SRCS_QQ := $(HEM_SRC_DIR)/peaks_bytebeat.cpp`. `popcountdi2.c`
already in `COMPILER_RT_SRCS` (ASR).

## Test plan (harness/tests/test_oc_app_QQ.cpp)

- Factory/registration: GUID `OCQQ`; 200 exposed settings (`kIoParamCount + 200`).
- Subset remap: within-channel logical 2 maps to physical 3
  (`CHANNEL_SETTING_SOURCE`), not the mask; the mask keeps its U16 default.
- Draw renders.
- Output smoke: route clocks + CV, pulse a clock, assert the four DAC outputs are
  not all zero (ISR -> quantizer -> DAC runs). Exact pitch is hardware-smoke (the
  shim collapses the calibrated DAC to 1V/oct).
- Settings + mask round-trip: mutate exposed rows on each channel plus a mask per
  channel, serialise/deserialise, assert all survive (the whole-app blob covers
  the masks).
- Param sync: direction 1 via `parameterChanged`; direction 2 via
  `factory->customUi`. Offset push-back with `set_parameter_offset(1)`.

## Footer

### Recipe spot-check

DQ quad-facade template confirmed reusable at N = 4; the only deltas are the
channel count (4 not 2), a single mask skip (index 2 not the 9..12 block), and the
`kMaxSettings` raise.

### Per-entry verification (3 settings traced against vendor)

- Index 0 `CHANNEL_SETTING_SCALE`: `{SCALE_SEMI, 0, NUM_SCALES-1, "Scale",
  scale_names_short, U8}`. int16-safe. Exposed (logical 0).
- Index 2 `CHANNEL_SETTING_MASK`: `{65535, 1, 65535, "Active notes", NULL, U16}`
  (APP_QQ.h:1163). Overflows int16. Excluded.
- Index 3 `CHANNEL_SETTING_SOURCE`: `STORAGE_TYPE_U4`. int16-safe. Exposed at
  within-channel logical 2 (mask skipped).

3 of 3 consistent with vendor source.

### Shim prereq verification

- OC aggregation supplies braids_quantizer + OC_scales; only `peaks_bytebeat.cpp`
  is a per-app vendor dep. `util_logistic_map`/`util_turing`/`util_integer_sequences`/
  `OC_visualfx`/`OC_scale_edit` header-only and portable.
- `util_integer_sequences.h` quote-includes vendor `../OC_strings.h`; the shim
  OC_strings poison handles it because the per-app `.cpp` pulls shim OC_strings.h
  before APP_QQ.h.
- HSIOFrame.h risk: see brainstorm. Resolve at first compile; no vendor edit.
- GUID `OCQQ` unused.
